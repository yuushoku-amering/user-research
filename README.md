# 岚苔 Vesper · 用户研究工作台

> **岚苔 Vesper**（名字取自「雨前的空气」）是一个**跑在你自己电脑上**的用户研究工作台：
> 从访谈转写稿到统计分析，九个组块一条链。
> 不需要写代码，打开浏览器就能用；所有数字由本机 Python 算出来，**不经过任何模型**。

> **📌 关于这个项目**
>
> 本工作台**仅为初期测试**，旨在帮助学生、专业工作者进行社会调研与用户研究。
> 你可以**用大白话说明需求** —— 由工作台给出问卷设计、数据分析方法的建议，
> 并辅助完成数据处理等操作。所有判定都会写明依据，你可以追问、可以推翻。
>
> 它离"完成"还远（下面列了明确没做完的部分）。
> **非常希望能得到你在使用中的建议与反馈** —— 哪句话看不懂、哪个数算得不对、
> 哪一步多余，都欢迎告诉我们。
> 👉 [开一个 issue](https://github.com/yuushoku-amering/user-research/issues)

## 想先看看它能干什么：双击 `试一下_演示.bat`

不用装什么、不用先建项目、**也不用开浏览器** —— 它会自己造一份合成问卷
（412 份，里面埋了一条真实的效应），然后跑给你看：

```
⑤ 数据预处理  →  ⑥ 统计分析  →  把结果摊开给你看
```

你会看到（**都是真算出来的数**）：

- 它先**复述一遍**「我理解你要问的是什么」
- 然后摊开**决策树**：为什么选了 t 检验、为什么前提不过要换秩方法
- 给的是**结论 + 95% 置信区间 + 效应量**，不是光一个 p 值
- 一道 **SPSS 语法**，让你在 SPSS 里跑同一件事交叉核对
- 它主动报出的缺失与异常值 —— 并且**没有替你填、没有替你删**

> ⚠ 名字里那个"五分钟"是说**看完**要五分钟；机器跑只要几秒。
> 跑得快正是这东西想证明的事：**算数不该是瓶颈，判断才是。**

> **`安装依赖.bat` 是干什么的**：它把"装依赖"这步变成一次双击 ——
> 自动找 Python → 按 `requirements.txt` 装 → **真的 import 一遍**验证 →
> 把结果写成 `install-report.txt`（UTF-8，控制台乱码也能看）。
> 失败了会告诉你常见原因（多半是 Python 版本太新、没有 wheel）。
>
> 想装可选的（读 SPSS `.sav` 的 pyreadstat、跟 sklearn 对拍用的），
> 跑 `python -m pip install -r requirements-optional.txt`，或
> `安装依赖.bat --optional`。
>
> **不想装 Python？** 那就用上面的**便携版** —— 它是同一个程序，只是把 Python 一起打包了。

**`config.json` 不用手动建** —— 不存在也能跑（走自动探测）。
想改端口、指定自己的 Python，再把 `config.example.json` 复制成 `config.json` 改。
界面右上角 **⚙ 设置**也能改这些东西（SPSS 路径、模型 API）。

## 它想解决什么问题

会做用户研究的学生，卡住的地方通常不是"不会算"，而是这三件：

| 卡在哪 | 工作台怎么接 |
|---|---|
| **不知道这一步该干什么** | 九个组块按顺序排好，每个都有「需要什么材料、产出什么文件、下一步去哪」 |
| **不知道这个方法该不该用** | 决策树把「为什么用这个、为什么不用另一个」写进报告；前提不满足会当场停下来问你 |
| **不知道自己算错了** | 见下面「几条刻意的设计」——这是这个项目和"跑个脚本"最大的区别 |

它**不是**要替你理解材料，也不是要替你做方法论判断。它负责的是：
**把材料摆整齐、把该报的数字报全、把可疑的地方指出来。**

## 几条刻意的设计（这些是这个项目的重点）

### 1. 模型不参与算术

所有数字都来自本机的 `pandas / scipy / numpy`，代码可读、可改、可复核。
模型通道（默认关）只做"给初稿"的事——比如生成提纲初稿、把大白话拆成结构化意图。
**推荐方法这件事也是确定性规则算的，不是模型猜的**：规则写在
`knowledge/统计分析判定.md` 里，研究员能看、能改、能追问出处。

### 2. 有些话它应该直接说"你的数据答不了"

输入「**花钱多的同学是不是更容易分手**」，它会先在推荐方法之后告诉你：

> ⚠ 你这句话里，有一部分是**这份数据答不了**的
> 命中「更容易」（跨截面不能推因果）
> **要回答它需要**：有时间先后、至少两次测量
> **我现在能给你**：相关或组间差异，并写明「只能说明同时发生」
> **想要真答案就得**：补一次追踪测量；或改用实验/准实验；或用访谈补机制这一层

**只拦不给出路，会把学生堵死。** 所以每条约束都强制填「降级路径」。
这份清单在 `knowledge/数据能支持什么.md`，**可以自己加条目**（字段结构锁死）。

### 3. 会报"这个结论由谁决定"

相关分析跑完，它会多给一张表：

| 版本 | n | Pearson r | R² |
|---|---|---|---|
| 含全部 | 539 | 0.257 | 0.066 |
| 去掉那 3 个 | 536 | **0.706** | **0.499** |

> ⚠ **结论由少数个体决定**：去掉这 3 个（占 0.6%），r 从 0.257 变成 0.706。
> **这不代表他们是「坏数据」**——删不删、怎么处理是你的事；但报告里必须写明这一点。

它**不删数据、不改主结果**，只把事实摆出来。

### 4. 三件"看起来对、其实是假精确"的事，它会拦住

| 坑 | 它怎么做 |
|---|---|
| **均值填补**（把方差压小、相关稀释、p 值偏乐观） | 并排给出「完整个案 / 均值填补 / 多重插补」三种结果，**让代价可见** |
| **给秩相关配 r² 当"解释力"** | 连续×连续**三个系数一起报**（Pearson/Spearman/Kendall）+ 一句差异说明 |
| **只报 p 不报区间** | 相关、均值差、回归系数、OR、效应量……全部带 **95% CI** |

### 5. 前提检验分得清"该换方法"和"不该换"

配对检验的前提**落在差值上**，不是原始两列各自正态——
前后测两列都偏得厉害、但差值正态时，配对 t 完全没问题。
只看"两列各自正态吗"就换非参数，会白丢配对带来的检验力。

### 6. 跳题 ≠ 漏答

「没谈过恋爱的人不答花销题」是**结构跳题**，不是漏答。
工作台会把两者分开，并在你选「整行删除」时警告：
**那会把跳题的人整群删掉**，而报告里还看不出来。

## 九个组块

| | 组块 | 干什么 | 主要产出 |
|---|---|---|---|
| ⓪ | 研究设计 & 主题澄清 | 把模糊的研究兴趣收敛成可执行的问题 | 研究简报 |
| ① | 访谈提纲设计 | 按研究问题生成提纲 + 追问方向 | `contracts/interview_guide.md` |
| ② | 访谈记录编码整理 | 转写稿切成发言单元，生成能直接填的编码工作表 | `output/编码工作表.csv` |
| ②b | 编码汇总 | 把你填的码数成「范畴 → 主题」，并挑毛病 | 主题矩阵、覆盖度、候选引语 |
| ③ | 问卷设计 | 把研究问题转成题项表 | `output/问卷_题项表.csv` |
| ④ | 问卷数据统计 | 样本概况 / 频数 / 描述 / 交叉表 / **信度 / 效度（因子分析）** | 一堆频数表 + 报告 |
| ⑤ | 数据预处理 | 缺失值（含**多重插补**）/ 异常值 / 反向题 / 合成变量 | `output/clean_data.csv` + 处理日志 |
| ⑥ | 统计分析 | 决策树选方法 → 前提检验 → 算 → **双轨生成 SPSS 语法** | 分析报告 + `.sps` |
| 🔒 | 去标识化 | 直接标识符替换、准标识符提示、编号对照表 | 脱敏文本 + 报告 |

**⑥ 支持的分析**（2026-09 现状）：

- 组间差异：t / Welch / ANOVA + Tukey / Mann-Whitney / Kruskal-Wallis
- 配对与前后测：**配对 t / Wilcoxon 符号秩 / 单样本 t**
- 关系：Pearson / Spearman / Kendall 三系数并出、**偏相关**、多元回归
- 分类：卡方 + Cramér's V
- 预测：**二元 logistic 回归**（OR + OR 的 CI、Hosmer-Lemeshow、分类表）
- 因果：**中介分析**（bootstrap 间接效应）、**调节分析**（简单斜率 + Johnson-Neyman）
- 效度与信度：**因子分析**（PCA/主轴因子 + varimax + KMO + Bartlett + 平行分析）、Cronbach α
- 数据处理：**多重插补（MICE）+ Rubin 合并**、**加权分析**（n_eff / 设计效应）
- 全局：**多重比较登记簿**（跨分析累计，给 Bonferroni / FDR 门槛）

├── web/                       前端（原生 JS，无构建步骤）
├── _demo.py                   演示：从一份问卷跑到一个结论（上面那个 .bat 调它）

**组块是插件**：主程序不认识任何组块。加一个组块 = 建一个目录放两个文件。
这套设计已经吃过教训——**同一件事写两遍，两边规则不一致，而且从不报错**，
所以现在凡是有"两处都要用"的判定，都强制只有一份实现，并有测试守着。

## 上手之后

### 项目放在哪

第一次打开时它让你选一个目录当「项目之家」，你的每个研究项目都是那下面一个子目录
（`contracts/ data/ samples/ output/ _history/`）。

**项目不会进这个仓库** —— 仓库里只有软件本体。
这样做有个实在的好处：研究材料（访谈原稿、编号对照表）本来就不该和代码混在一起，
而且下次更新软件时也不会碰你的数据。

### 服务是怎么跑的

服务只在 `127.0.0.1` 上听。**关掉那个黑色命令行窗口 = 停服务。**
开机不自启、不写注册表、不建计划任务、不留后台进程。

改了 `server.py` 或 `core/` 里的东西要重启才生效 —— 双击 `重启工作台.bat`；
只改了 `web/` 的话刷新页面就行（必要时 `Ctrl+Shift+R` 强刷）。

### ⚙ 设置（顶栏那个齿轮）：SPSS 路径 + 模型 API

两个**可选**功能都在这一页配，不用手改 `config.json`：

- **SPSS**：「📁 浏览…」选 `stats.exe`，或点「🔍 自动找」在常见安装位置里扫一遍
  （只查文件、**不会启动 SPSS**）。找到几个位置会列出来，每条旁边有「用这个」。
  没装 SPSS 完全不影响其它功能 —— 照样生成 `.sps`，你自己拿去跑就行。
- **模型建议**：两条路选一条 ——
  **自带 API**（填接口地址 / 密钥 / 型号，点「测试连接」，走标准 OpenAI 兼容接口，
  所以 DeepSeek、硅基流动、智谱、本地 Ollama 都能填）；
  或者**什么都不配**，用「📋 复制任务书 → 贴到任意聊天窗口 → 结果贴回来」。
  **密钥只写在本机 `config.json`（不进仓库）、界面不回显、接口不返回原文。**

报错都翻译成人话：401「密钥没复制全」、404「地址要写到 /v1 这一层」、
连不上会提醒「这台机器 curl 是坏的，但 Python 走的是另一条路，别拿 curl 判断」。

## 自测

```bash
python _runall.py          # 一条命令跑全部 32 套（Python + 前端）
python _runall.py --py     # 只跑 Python
```

`_runall.py` 会**先记下你当前打开的项目**，跑完检查配置有没有被测试弄乱、
被弄乱就用「最近项目」找回来——测试可以弄乱临时目录，但不许弄乱你的工作现场。

**测试不依赖你机器上的任何项目，也不需要仓库里有素材文件。**

素材是**跑测试时现场造**的：定义在 `_fixtures.py`（那个程序会在
`_jobs/fixtures/` 下把问卷、访谈稿、编码表都算出来，固定随机种子，谁跑都一样）。
`_runall.py` 会先造一次，所以 clone 下来直接 `python _runall.py` 就该是 32 套全绿。

**为什么素材本身不进这个仓库**：那几份访谈稿是**故意带真名、手机号、学号**的
（去标识化那一棒要拿它们当靶子）。全是编的，但一份公开仓库里躺着
「看着像真访谈记录」的文件不合适——别人不会知道那是假的。仓库里只留"怎么造"。

几个专项自测值得单独跑：

| 文件 | 守什么 |
|---|---|
| `_statstest.py` | 有序档位/区间没被当成数字；**三个相关系数都在、CI 必须包含点估计** |
| `_regresstest.py` | logistic 的系数要和 sklearn 对得上；OR 的 CI 要在对数尺度上算 |
| `_mediatetest.py` | 中介的间接效应要对上真值；**JN 转折点要真的对应显著性翻转** |
| `_factortest.py` | varimax 的两条**定义级**性质（准则变大、总方差不变） |
| `_imputetest.py` | 均值填补的代价；Rubin 合并的总方差 > 组内方差；权重相等时 DEFF=1 |
| `_scan_quotes.py` | 不是测试，是工具：编译全部 .py，只报真会崩的 |

## 诚实的部分

**它做不到的**（所以做不到就别硬做）：

- 聚类、判别、生存分析、混合模型、结构方程 —— 没有
- 复杂抽样设计的方差估计 —— 只有基于权重的近似
- **因果推断**：中介/调节给的是"统计上的路径"，**不是因果证明**。
  那要靠时间先后或实验设计，不是靠统计
- **它不知道你的数据是怎么来的**。权重怎么来的、缺失是随机的还是有选择的，
  这些只有研究员知道——工作台会在报告里要求你写清

**还没有的**：一键把分析结果拼成论文格式的表格（有意不做，见下）。

**设计上刻意拒绝做的事**：

- 不生成"能抄进论文方法部分"的成稿 —— 方法段落是你的判断，程序只给依据
- 不自动删数据（极端值只标记、两版并报，删不删是你的事）
- 不替你给因子命名、不替你定主题名字
- 检测再聪明也会漏（同形字、位置错位、昵称）→ 所以界面上永远能自己改

## 平台

**目前只在 Windows 上验证过。** 三个启动脚本（`启动工作台.bat` / `重启工作台.bat` /
`_find_engine.bat`）和 `_read_config_python.ps1` 都是 Windows 专用的。

服务端本身是纯 Python 标准库，理论上 Mac / Linux 也能跑：

```bash
python3 server.py --no-open      # 然后自己开 http://127.0.0.1:8765
```

但 `core/paths.py` 里的 Python 探测表、`core/spss.py` 里的 SPSS 调用路径都是 Windows 写法，
**没有在别的系统上试过**。想在 Mac/Linux 上用，欢迎开 issue 告诉我卡在哪。
