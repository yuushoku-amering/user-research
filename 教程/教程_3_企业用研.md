# 教程 ③ · 企业用户研究者（要交东西、要合规、要复用）

> 你关心的不是"它多聪明"，是**能不能少返工、能不能过审、能不能沉淀**。

---

## 一、它解决的是这三件事

| 痛点 | 它怎么解 |
|---|---|
| 每次研究都从零写设计、问卷、报告 | 研究设计落 `contracts/`，后面**全部继承**；改一处，问卷和统计跟着对齐 |
| 原始材料到处飘，真名手机号进了汇报稿 | 🔒 强制第一站：脱敏稿 + `格式说明.md` + 去标识化报告，**可核查** |
| 结论说不清强度，容易被业务方过度解读 | ⑥ 每次输出都带「**这个结论能说到什么程度**」——照抄即可 |

**它不是**：不是自动化决策工具。结论强度、样本代表性、要不要匿名，全部由你判断并留痕。

## 二、交付物是什么（能直接给出去的东西）

```
contracts/research_brief.md     研究设计（目的 / 研究问题 / 变量与操作化 / 对象）
contracts/interview_guide.md    访谈提纲
contracts/survey_design.md      问卷设计说明（含每题的设计依据）
contracts/coded_transcript.md   编码后的转写稿（② / ②b 回填）
output/编码工作表.csv            编码表（要你逐段填的那张，含引语候选）
output/访谈_初步分析.md           关键词与引语候选（② 的线索）
output/编码汇总.md               范畴 → 主题（**每条结论配原话**，汇报直接引）
output/编码汇总_主题.csv          主题层汇总
output/编码_主题矩阵.csv          主题 × 受访者覆盖矩阵（看"几个人说到"）
output/问卷_题项表.csv            给问卷星/腾讯问卷排版用
output/问卷_概要.md              描述统计
output/clean_data.csv           清洗后的数据（分析用）
output/预处理日志.md             清洗做了什么、缺失怎么处理的（留痕）
output/分析报告.md               统计结论 + 能说到什么程度 + 多重比较总账 + 结论敏感度
output/分析_语法.sps             SPSS 语法（复核用）
output/SPSS输出_*.html           装了 SPSS 时：它的原始输出（内嵌在结果页里）
output/脱敏_*.txt                可对外流转的材料
output/脱敏格式.md               这份材料程序怎么理解的（交接/复核用）
output/去标识化报告.md            换了什么、哪些只提示、哪些是高敏（合规留痕）
```

**"每条结论配原话"这一条在汇报里最有用**：业务方问"凭什么这么说"，直接翻到那一段。

## 三、合规这块（PIPL / 伦理）

去标识化按**三层**做，和一般"查找替换"不是一个量级：

1. **直接标识符 → 直接替换**
   姓名（含上下文昵称、同形地名）、手机（含带分隔符/全角写法）、身份证、邮箱、QQ/微信、学号工号、银行卡、座机、车牌
2. **准标识符 → 只提示，你决定**
   精确出生日期、**单位+部门**、精确地点/时间、罕见特征。理由是**组合风险**——单独看都不致命，凑起来能定位到人
3. **敏感个人信息（PIPL）+ 调研特有高敏话题 → 单独拎出来**
   生物识别（**含音频原声**）、宗教、特定身份、医疗健康、金融账户、行踪轨迹、**不满十四周岁未成年人**；
   调研里还加上：**性/亲密关系、心理健康、成瘾行为、违法经历、收入与负债、家庭暴力、政治倾向**

**几个实操要点**：

- **音频原声本身就是直接标识符**——转写稿脱敏了不代表录音能外发。报告里会提醒这一条
- **截图/图片不做识别**（不接 OCR，理由是要把图上传云端）。你自己用系统自带提取文字，或人工处理
- **`编号对照表.csv` 本身是敏感文件**——它写着谁换成了什么。默认不生成，勾了才生成。要和脱敏数据**分开保管**，按伦理要求销毁
- **编号两种模式**：默认按出现顺序（`[姓名1]`）；材料里有编号列时可选**按序号**（`[姓名R07]`，方便对回原始记录）。
  ⚠ 后者把"第几条"留在稿子里，**匿名强度略降**，对外发布能否接受要你自己拍板
- **去标识化 ≠ 匿名化**：这里是**可复原**的（有对照表就能还原）。要真匿名得销毁对照表和相关记录

## 四、团队协作与复用

| 需求 | 现状 |
|---|---|
| 换人接手 | 项目是整个文件夹，`contracts/` 写清了"为什么这么设计"；`格式说明.md` 写清了材料怎么读 |
| 版本追溯 | 产物直接改也行，旧版自动进 `_history/`；能对比两版、给版本写说明 |
| 归档 | 一键导出快照（含表单填写状态），导入回来接着做 |
| 沉淀方法 | 领域判定都在 `knowledge/*.md`，**是数据不是代码**，并且每条注明性质与出处：<br>`kind` = 行业惯例 / 某家观点 / 经验法则 / 工作台自身 |
| 换项目 | 不用重训。领域知识（抽样、访谈技巧、统计口径）跨项目复用；只有**材料怎么切**要现场确认一次 |

**建议的一条团队规范**：
- `data/` `samples/` 只放**原始**材料，永不修改
- 对外流转只走 `output/脱敏_*.txt`
- 对照表单独目录、单独权限，用完按流程销毁

## 五、一条典型的项目时间线

```
Day 1  ⓪ 研究设计（1~2h，最值钱的一步）
       🔒 把历史材料脱敏归档
Day 2  ① 提纲 → 访谈 → 🔒 脱敏转写稿 → ② 拆 → 边访边编码
Day 3  ②b 归纳主题（先出质性结论，业务方可以先看到东西）
Day 4  ③ 问卷设计 → 投放
Day 5  ④ 描述统计 → ⑤ 预处理 → ⑥ 检验 → 分析报告
Day 6  用 ⓪ 的研究问题做目录，把质性 + 量化拼成一份汇报
```

**两条经验**：
- **质性先出结论**（②b 就有可汇报的东西），不要让业务方等完整份量化
- **汇报里的每个数字，都能在 `output/` 里找到它的出处**——这是它相对"手搓 Excel"最实在的好处

## 六、要留意的三件事

1. **⓪ 的变量表是命门**。操作化定义写得含糊，③ 的问卷和 ⑥ 的统计都会跟着含糊——**这不是程序的问题，是设计的问题**，程序只会老实告诉你哪里继承不到东西。
2. **提醒要当回事**。它会把"拿不准"的地方摊出来（歧义号码、认不出的词、覆盖不足的主题）。**看过的可以关**（点「🙈 这条不用再问」，记在项目里）；但**别养成闭眼关的习惯**。
3. **SPSS 那一遍现在是自动的**（2026-09 改过）：程序会先用 `stats.exe -production`
   安静跑一遍，**跑完把 SPSS 的原始输出嵌进结果页**，两边数字对得上才交。
   安静跑不通时它会**替你打开 SPSS** 并载入语法，提示你按 `Ctrl+A` / `Ctrl+R`。
   ⚠ **对外交付的数字仍然建议人工复核一次** —— 自动化只是省掉"手工点一遍"，
   不是省掉"你签字"。也提醒一句：**它会启动 SPSS**，不接受的话就别在 ⚙ 设置里填路径。
