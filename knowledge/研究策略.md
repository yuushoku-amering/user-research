# 研究策略：方法怎么选 · 什么时候算够 · 结论按什么排

三条**策略层**的规则。它们和「研究问题与样本量」那份的区别：
那份管"写得对不对"，这份管"**选得对不对**"。

## 一、方法要和你想知道的东西对得上

| 你想知道的是 | 该用的方法 | 为什么 |
|---|---|---|
| **人实际上怎么做**（流程、习惯、说不清的默会动作） | **情境访谈 / 实地观察** | 这类事本人常常讲不清，得看他做。问他"你平时怎么用"得到的是他以为的自己 |
| **想法、动机、决策依据**（心里怎么想的） | **半结构深访** | 这是深访最强的地方；生成式研究里最万能的默认选项 |
| **一段时间里的变化**（什么时候会做、触发点、习惯怎么形成） | **日记法** | 靠回忆答不准，要"发生时记" |
| **某个界面好不好用** | **可用性测试** | 5 人就能发现大部分问题（见另一份的样本量规则） |

**最容易踩的错**：研究目的写的是"**实际怎么做**"，方法却选了深访。
深访问出来的是**他自己叙述的做法**，和实际做法常常是两回事——
这个错不会让研究跑不起来，只会让结论**看起来有依据、其实测的是另一件事**。

**方法不确定时**：默认半结构深访。它最通用，也最容易做好。

## 二、什么时候算"访够了"（饱和）

**经验判据**（不是精确算法）：

- 连续 **2–3 位**受访者没有提出**新的**范畴/主题 → 可以认为接近饱和
- 样本量已经落在研究类型的常见区间里（见「研究问题与样本量」那份）
- **饱和不是一个可以事后"算"出来的数**。它是你听材料时的判断：
  新来的一份材料还在让你改编码本吗？还在改，就还没够

**两条提醒**：
- 某个主题只有 1 个人提过，**那不是模式**，是个案——报告里要么单列，要么标明
- 受访者全来自同一个小圈子（同一个班、同一家公司）时，**饱和会被高估**：
  圈子内部共识本来就多，不是"大家都这么想"

## 三、结论按什么排（优先级框架）

分析之前先想清楚：**这批结论最后按什么标准排序**。不先定，报告就会出现
"重要的和有趣的花边并列"。

| 研究目标 | 排序框架 |
|---|---|
| 修可用性问题 | **严重度 × 频次**（又严重又常见的最先修） |
| 找市场机会 / 创新点 | **机会打分**（重要性高、当前满意度低 = 机会大） |
| 定 MVP / 迭代范围 | **影响 / 成本矩阵**（先做高影响低成本的） |
| 高风险方向的探索 | **假设画布**（风险 × 感知价值） |
| 产品战略 | **机会解决方案树**（从目标往下拆机会） |

**学术场景的对应**：论文里不需要商业框架，但要**说清排序标准**——
按理论贡献、按实践意义、还是按现象普遍性。**不能不给标准就排序**。
