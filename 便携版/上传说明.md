# 便携版怎么发布（上传说明）

> 这份是给维护者看的。做好的包在 `dist_便携版\岚苔Vesper-便携版.zip`。

## 为什么不上传到 GitHub 仓库

**体积超了**：便携版 zip 约 **120 MB**，而 **GitHub 单个文件上限 100 MiB**（硬限制，`git push` 会被服务端拒绝）。

所以分两处放：

| 放哪 | 放什么 |
|---|---|
| **本仓库（GitHub）** | 源码 + 打包脚本 + 说明（就是 `便携版/` 这一套，几百 KB） |
| **阿里云盘** | 便携版 zip（约 120 MB，国内下载快） |
| 本机 `dist_便携版\` | 构建产物，**不要提交进仓库**（已在 `.gitignore` 里） |

## 怎么上传（手动，3 步）

1. **拿文件**：`dist_便携版\岚苔Vesper-便携版.zip`
2. **传到阿里云盘**：把 zip 拖进去，**右键 → 分享 → 创建分享链接**
   - 有效期建议选**长期**（不然过一阵链接失效，README 里的下载入口就废了）
   - 有"提取码"就记下来
3. **把链接填进 README**：仓库根目录 `README.md` 里搜 `【便携版下载】`，
   把那行换成真实链接（形如 `https://www.alialiyundrive.com/s/xxxxxx`，提取码 `xxxx`）

## ⚠ 发之前必须确认的四件事

打包脚本 `打包便携版.py` 会自动跑这四关，**任何一关不过它会打印 `[FAIL]` 并返回退出码 1**：

1. 内置 Python 换路径后 `sys.prefix` 跟着走（不然换台机器就坏）
2. 四个核心包能 import，而且**真画得出一张图**（matplotlib + PIL）
3. `pip check` 没有缺依赖
4. `_demo.py` 全流程跑得完（目前约 10 秒）

```
python 便携版\打包便携版.py        # 看到 "[OK] 全部验收通过" 才算成
```

**另外请人肉确认一件事**（脚本验不了）：**把 zip 解压到另一台机器上、双击一次**。
脚本是在本机跑的，换机器才可能暴露路径/权限类的问题。

## 版本号怎么标

推荐在分享里写清版本与日期，README 也带上，方便用户对照：

```
岚苔Vesper-便携版-v1.0-20260927.zip     （约 120 MB）
```

## 以后更新便携版

1. 改完代码，`git pull` / 本地改完
2. `python 便携版\打包便携版.py`（约 4 分钟）
3. 把新 zip 传到阿里云盘，**创建新分享或更新已有分享**
4. 更新 README 里的文件名/日期

> 用户那边**只要把新 zip 解压、把旧的 `岚苔Vesper\` 文件夹换成新的**就行 ——
> 他们的**研究项目不在这个包里**（项目建在用户自己选的「项目之家」），所以不会被覆盖。

## 想走 GitHub Release 也行（可选）

如果哪天想省掉网盘那一步：GitHub Release 的附件**允许单文件最大 2 GiB**（不受仓库 100 MB 限制）。
办法是建一个 release、把 zip 作为 asset 传上去，README 里指向那个 release 页面。

需要 GitHub API token（`repo` 权限），所以这一步得你在网页上点，或者给我 token 我来写脚本。
