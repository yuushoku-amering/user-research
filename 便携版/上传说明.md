# 便携版怎么发布

> 这份是给维护者看的。做好的包在 `dist_便携版\岚苔Vesper-便携版.zip`。

## 现在怎么发：GitHub Release（就这一条路）

**发布地址**：仓库 → Releases → 新建一个 release（目前是 `v1.0`），
把切好的分片和辅助脚本当 **Assets** 传上去。

**每次要传这 5 个文件**：

```
Vesper-portable.zip.001    45 MB  ┐
Vesper-portable.zip.002    45 MB  ├ 三个分片
Vesper-portable.zip.003    32 MB  ┘
merge-parts.bat                   ← 用户双击它来合并
part-info.txt                     ← 中文说明 + 原文件 SHA256
```

要把整包切成这样：

```powershell
python 便携版\分片.py split dist_便携版\岚苔Vesper-便携版.zip
```

> 为什么切成 45 MB 一片 —— 见下面「为什么」两节。
> README 里的下载入口指 `/releases/latest`，所以以后发 `v1.1`、`v1.2`
> **只要建新 release 就行，README 不用改**。

## 为什么不用网盘（阿里云盘实测被拒）

一开始打算把整包放阿里云盘。实测：上传 zip 之后想建公开分享，它给的是

> 当前所选文件全部不支持公开分享，你可以使用快传功能

**那是它的策略限制，不是文件损坏或违规**（压缩包是重点被限的类型之一）。而"快传"是点对点临时传：
**有效期最多 1 天、保存人数 1 人** —— **没法当公开下载入口**（挂在 README 上等于摆个死链）。

参考：[阿里云盘「部分内容不可分享」](https://baijiahao.baidu.com/s?id=1817969929597972677)、
[分享的链接对方不能下载](https://developer.aliyun.com/ask/606803#1)、
[阿里云盘怎么分享压缩包](https://www.php.cn/faq/1168042.html#1)

⇒ 所以干脆不用网盘：**切成 45 MB 小片直接进 Release**。
（切片的另一个原因见下：整包 122 MB 撞 GitHub 单文件 100 MiB 硬限制。）

> 哪天想加个网盘镜像也行 —— 用**同一批分片**，不用重做；
> 但那是备用，主入口保持 Release。

## 为什么不上传到仓库本体

便携版整包约 **122 MB**，而 **GitHub 单个文件上限 100 MiB**（硬限制，`git push` 会被服务端拒绝）。

切成 45 MB 一片之后三条路都通了：

- **Release 附件**：单文件上限 2 GiB，随便传
- **仓库本体**：每片都小于 100 MiB，那条限制也不再撞
- 不再依赖任何网盘的分享政策

```
Vesper-portable.zip.001   45 MB   ┐
Vesper-portable.zip.002   45 MB   ├ 用户全下下来
Vesper-portable.zip.003   32 MB   ┘
merge-parts.bat                   ← 双击它
part-info.txt                     ← 中文说明 + 原文件 SHA256
```

### ⚠ 文件名必须是纯 ASCII（分片也算）

**GitHub Release 的附件名只收 ASCII**，而且它是"能留则留"。2026-09-27 实测两种表现：

| 本来的名字 | GitHub 上变成 | 问题 |
|---|---|---|
| `合并分片.bat` | `default.bat` | 整串没有 ASCII 片段 → 降级成字面的 default |
| `岚苔Vesper-便携版.zip.001` | `Vesper-.zip.001` | 削掉中文后剩个莫名其妙的 `Vesper-` 尾巴 |

⇒ 所以现在**全都生成纯 ASCII 名**：
`Vesper-portable.zip.001~003` / `merge-parts.bat` / `part-info.txt`，
**中文说明写在 `part-info.txt` 的内容里**（文件内容什么编码都行，文件名不行）。

> zip **内部**的目录名仍然是 `岚苔Vesper-便携版\`（中文在 zip 里不受影响），
> 用户解压后看到的还是那个熟悉的中文文件夹名。

**用户那边**：下全几片 + `merge-parts.bat` 放同一个文件夹 → 双击 → 合成 zip → 解压 → 双击 `start-portable.bat`。
合并脚本**不需要装任何东西**（用 Windows 自带的 `copy /b` 和 `certutil`），
并会打印 SHA256 让用户跟 `part-info.txt` 里的对上。

> ⚠ 这里踩过一次设计矛盾：合并脚本原本想用**包里自带的 Python** ——
> 可那个 Python 还在 zip 里、而 zip 正是要合并出来的东西（先有鸡还是先有蛋）。
> 现在完全不用 Python，这个矛盾就不存在了。

**已实测**：切 3 片 → 干净目录里双击 `.bat` → 合并出的文件
**127,935,716 字节、SHA256 `6b9cb957…165274df`，与原文件一字不差** → 解压 → `_demo.py` 退出码 0。

## 发布步骤（GitHub Release）

1. **做包**：`python 便携版\打包便携版.py`（约 4 分钟，它会自己跑四关验收）
2. **切片**：`python 便携版\分片.py split dist_便携版\岚苔Vesper-便携版.zip`
3. 仓库 → **Releases → Draft a new release**
   - Tag：`v1.1`（递增）
   - 标题：`岚苔 Vesper 便携版 v1.1 —— 自带 Python，解压即用`
   - 说明：直接抄上一个 release 的（改版本号即可）
4. **Assets 里传那 5 个文件**（三个分片 + `merge-parts.bat` + `part-info.txt`）
5. Publish。**README 不用改** —— 它指的是 `/releases/latest`

> 想自动化也行：GitHub Release 可以走 API 建（需要 `repo` 权限的 token）。
> 不过现在这样点几下也就几分钟，没必要上脚本。

## ⚠ 发之前必须确认的四件事

打包脚本 `打包便携版.py` 会自动跑这四关，**任何一关不过它会打印 `[FAIL]` 并返回退出码 1**：

1. 内置 Python 换路径后 `sys.prefix` 跟着走（不然换台机器就坏）
2. 四个核心包能 import，而且**真画得出一张图**（matplotlib + PIL）
3. `pip check` 没缺依赖（已删包的孤儿元数据算噪声，会滤掉）
4. `_demo.py` 全流程跑得完（目前约 10 秒）

```
python 便携版\打包便携版.py        # 看到 "[OK] 全部验收通过" 才算成
python 便携版\分片.py split <zip>  # 发布前切一下
```

**另外请人肉确认一件事**（脚本验不了）：**把 zip 解压到另一台机器上、双击一次**。
脚本是在本机跑的，换机器才可能暴露路径/权限类问题。

## 版本号怎么标

Tag 用 `v1.0` / `v1.1` 这样递增（release 页面自己会显示）。
**Assets 里的文件名不用带版本号** —— 它们挂在各自的 release 下面，
README 指 `/releases/latest`，用户不会混。

## 以后更新便携版

1. 改完代码
2. `python 便携版\打包便携版.py`（约 4 分钟，含四关验收）
3. `python 便携版\分片.py split dist_便携版\岚苔Vesper-便携版.zip`
4. 建一个新 release（tag 递增），把新分片传上去 —— **README 不用动**

> 用户那边**只要把新 zip 解压、把旧的 `岚苔Vesper\` 文件夹换成新的**就行 ——
> 他们的**研究项目不在这个包里**（项目建在用户自己选的「项目之家」），所以不会被覆盖。
